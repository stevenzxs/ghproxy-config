# GHProxy Implementation Plan

**Goal:** Publish controlled GHProxy build and deployment tooling to stevenzxs/ghproxy-config and deploy on 104.244.90.25 behind https://ghproxy.stevenzxs.cn.

**Architecture:** Keep product source in a separate upstream repository, pin a stable release and full SHA. Build through reviewed configuration-repository GitHub Actions and publish an immutable GHCR image. Join the existing deploy_sub2api-network and reuse sub2api-caddy; never create another gateway or overwrite existing sites/certificate volumes.

**Tech Stack:** Docker Compose, GitHub Actions, GHCR, existing Caddy, Python validation scripts.

## Approved design

- Configuration repository: https://github.com/stevenzxs/ghproxy-config; local D:/code/ghproxy-config.
- Target: root@104.244.90.25, linux/amd64.
- Domain: ghproxy.stevenzxs.cn, DNS A verified as 104.244.90.25.
- Existing gateway configuration: /opt/sub2api/deploy/Caddyfile; container sub2api-caddy; preserve deploy_caddy_data and deploy_caddy_config.
- Independent resource-limited GHProxy container, no publicly bound backend port, no disk cache initially.
- Implement only supported public GitHub download/clone paths; verify upstream supports smart HTTP before promising clone support.
- Access/abuse controls must be verified before anonymous public downloads are enabled.
- Back up current Caddy configuration, validate candidate, reload only existing Caddy, verify existing sites and new strict HTTPS endpoint; roll back only this change on failure.
